# Sections of a Netgent Workflow
- All netgent workflows are split into multiple states each of which has four components
    - Name, formated in the json as ("name": "Name of State Here",). The contents of the name have no bearing on the exectuion of the workflow although it is useful to have a descriptive name for debuging purposes. However their MUST be a name field as shown in formating or the workflow will not run. If you are running netgent in AI generation mode however the name is important as it will inform the AI what you are trying to achive.
    - Description, formated in the json as ("description": "Description of the proccess here",). The contents of the description have no bearing on the exectution of the workflow although it is useful to have a descriptive name for debuging purposes. However if you are using the AI mode to generate a workflow it is incredibly important to use a description that acuratly and sucinctly describes what you want the workflow to achive as it uses this field in determining what it should interpret your actions to do. For AI mode differnt descriptions even with the exact same action field contents will result in differnt results.
    - Checks, formated in the json as ("checks" : [ Each check desired goes here ], ). Netgent uses checks to determine which state should be performed. Netgent is fully order agnostic in terms of which order the states are written in, it only uses checks to determine which state should be run. States will only be executed in the event every check is satisfied and if a situation occurs where multiple states have all checks fufilled the workflow will throw an error and exit. If you are in AI generation mode the checks field will be generated by the AI based on what you write in the triggers section. Do note that the AI generation mode is not order agnostic and will run through state prompts from top to bottom.
    - Actions, formated in the json as ("actions" : [ Each action desired goes here ],). Actions are the meet of a netgent workflow with each state executing actions in its action field from top to bottom. In the event that an action can't be executed then the netgent workflow will exit. This most commonly occurs with click and type actions that are only provided a css selector, to avoid this provide the action with an x and y cordinate also. These cordinates will only be used if the css selector can't be found.

# Writing Usefull Checks
Checks are in one of three forms, checking if the URL is a specific URL, checking if their is a certain substring of text on the page, or checking if their is a certain CSS selector element located on the page. These checks all have differnt uses, a URL specific check should only be used if you are confident that you have the correct URL for the page, most likely meaning that you have navigated to the page in a previos state and you want to verify that you navigated to the correct page. It is important to note that webpages frequently redirect your url meaning that navigating to one URL does not garuntee that you will arive at that URL. As an example navigating to https://www.netflix.com/login will redirect you to a URL similair to https://www.netflix.com/login?serverState=Bgjru%2BvcAxK1AazE7x%2FuVM5g1ynel%2FqIEplIEI%2FWkEjrzwa%2BGQcba8waLncsoywDq5Mn%2FdF8qY%2Bj5iIVcOFZCdmEqzOa3T%2F1l1bJ3GdIF%2F%2F%2FNhEuvvlu5gmdYmmJHClFUvwbEipZAgf30eV5XWp5F59RdBGiwyiZqlNzUUN89k6At6Vc04cFHCe9yIYqB9%2BP1Pltzjfi%2B15ZhdCLb7YA8zp8PrBwW%2FiCd2Qpuc4fpnOLfZNSgmP9qt8Qmull0pgYBiIOCgw8%2BCkJ1OKBqLks5co%3D which would result in any check that looks at the URL to determine wether you have arrived at netflix.com/login determining that you have not. Next are text based checks which search a page for text, these are generally relliable however as a general rule if you can't highlight the text on the page and copy and paste it into a .txt document you should not use it in a check. This is becuase not everything on a page that is identifiable as text to the user will be considered text, as an example although the netflix login page whose link was previosly refrenced although to the human inspection the link obviosly has Netflix written on it from a human perspective, it will not be recognized as text by this check. Lastly CSS selector checks, these are useful for identifying if their is a particular CSS on a page however they should otherwise be avoided as some websites change their CSS layout fairly regularly making this method more brittle.

Text Based Check
'''
      {
        "type": "text",
        "params": {
          "text": "Text being check for goes here"
        }
      },
'''
URL Based Check
'''
      {
        "type": "url",
        "params": {
          "url": "chrome://new-tab-page/"
        }
      }
